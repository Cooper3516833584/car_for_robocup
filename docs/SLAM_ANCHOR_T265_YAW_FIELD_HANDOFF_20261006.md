## 4. 出车前要补齐的测量与工具

### 4.1 独立偏航真值和安装数据

- 在车体刚性部分固定一对相距尽可能大的高对比标记，使用俯视相机或经校准的光学角度设备，**同时拍到轮轴中心地面基准和车身标记**；先标定畸变、像素尺度、相机固定程度、时间偏移和角度不确定度。要判定 0.5°，独立角度误差应优于约 0.2°；达不到就只报告测量区间，不宣布 0.5° 合格。现场记录地面标记坐标、视频帧率和丢帧。
- 复测 T265 外壳与 `base_link` 的 x/y/z、朝向、左右安装/水平度、支架拧紧状态；记录 T265 序列号、USB 线/接口/供电、镜头前后视野、纹理、照明和反光。`docs/HARDWARE_MEASUREMENTS.md` 的部分安装值是候选推算，不可当实测真值。
- 同一视频中标记动作开始、首次非零轮速、最后非零轮速/指令归零、车轮物理停止、车身标记稳定时刻，以及停后 0.2/0.5/1/2/3 秒。依时间戳对齐后才计算“停后 T265 漂移 − 真实车体转角”；只用命令归零当车体停止会误判惯性/驱动延迟。
- 记录轮胎接触、地面材质/清洁、载荷、电压和是否有人接近/遮挡镜头。前进是已知较健康的对照，后退和左右旋转都必须测；不因调查偏航而忽略前进回归。

## 5. SLAM 锚点离群实车实测流程

**安全前置**：现场操作员确认空场、车轮/支架/USB 状态、电池、实体急停；安全观察员全程在车旁。先在静止状态建立新的 T265 与 sidecar 同一会话，确认 `/scan`、`/tf` 与 SLAM 锚点持续输出；约 5 Hz 发布设计以 `tools/localization_chain_report.py` 的 3.5 Hz 下限检查，不能用旧 8 Hz 判据误报。静止预检需有新鲜已接受锚点、T265 有效、事件无丢失。任一不满足，不启动动作。

1. **静止基线（无电机）**：≥30 秒记录原始 T265、桥接扫描/TF、`slam_anchor` 和融合状态。至少做 3 个新会话，并特意记录 sidecar 是否为新建会话；不要在运动中通过遮挡/拔线制造故障。确认时间戳单调、扫描/锚点速率、已接受锚点年龄及静止漂移。
2. **正常动作**：每动作单独预检，在相同起点/朝向/纹理与空场条件下，先前进 +20 cm、后退 −20 cm，再按场地空间做前进/后退 ±50 cm 与左右 ±90°；每类至少 3 条有效样本，左右顺序交错，异常样本保留并说明原因后补样。使用 `tools/closed_loop_motion.py`，由现场逐条确认三个 `--confirm-*` 选项，`--output` 指向 `/home/radxa/car_test_logs/` 下**不存在**的新目录；勿把示例 TOML 当实测配置。
3. **观察到自然离群时**：不追求通过人为遮挡在行驶中触发它。记录离群前后 ≥2 秒的扫描/TF 状态、锚点原始时间与接收时间、新息平移/偏航、候选序号/一致性、已接受年龄、融合单步位移/偏航、动作命令、是否安全停车。按 `slam_anchor` 事件计数：孤立大新息不应改写融合姿态；连续 3 帧相互一致且仍在 1.0 秒窗口内的候选应完成平滑迁移，动作不中断。若候选持续不一致、超 1.0 秒、桥接真断流或 T265 无效，必须维持现有安全停车。
4. **真失效保护**：仅在车轮停止的独立诊断会话内检查 SLAM 停流、TF 不更新、T265 断流的状态分类与日志；需验证运动中安全停车时，使用有审核的仿真/回放或专门受控台架。不得在正在行驶的小车上拔 USB、停 ROS 或挡镜头来“测停车”。

每条样本分别给出 `bridge`、`fusion`、`motion` 三层结论。主要通过条件：健康桥接下的短时三帧确认**没有误停车**、未把孤立离群注入融合位姿、真实失效没有继续发非零运动命令、前进/后退性能未较历史有效样本退化。未出现自然离群时，正常动作只能证明一般连续性；离群路径须由离线回放证实，不能因“没触发”而写实车通过。历史 0.10 m 新息门、三帧一致性和 1.0 秒上界不得为追求通过率擅自放宽。

## 6. T265 偏航解决路径与实车验证

### 6.1 先用真值定位因果层

1. **静止与手动旋转、无电机**：固定同一定位会话，静置 ≥30 秒；由现场人员缓慢手动将车体标记转至外部角度参考的 +90°、−90°，每方向至少 3 次，停稳后连续记录 ≥3 秒。对比原始四元数、原始角速度、适配后偏航、融合偏航、锚点接受事件与视频真值。手动移动本身可能污染 SLAM，须单独标注。
2. **低速电机旋转**：沿用第 5 节的单动作 ±90°，每方向至少 3 条干净样本。同步标出车轮/车身物理停时及命令停时。计算 `(T265_t − T265_停稳) − (外部角度_t − 外部角度_停稳)`；误差持续变化且真值不动，才支持 T265 估计收敛。若真值同步变化，则调查轮胎/驱动/控制停稳；若仅融合变化，则调查 SLAM 锚点或融合迁移；若原始四元数稳定而适配偏航变，则调查时间、坐标或重基准；若相机外壳与车身标记相对移动，先修安装。
3. **对照场景**：同一方向和速度在原位置做重复，再仅改变纹理/光照做静止与手动试验；记录 T265 confidence、USB 帧率/超时、启动预热长度。另保留前进 +50 cm 和后退 −50 cm 对照，检查 yaw 漂移与横移，避免修转向后破坏已经稳定的直线运动。

### 6.2 按证据选择定位链最小修复

- 若找回的阶段 4 代码与现行链路的某个**定位层**差异，在同输入回放中复现了偏航变化，保留现行 SLAM 离群/断流保护，只回退或修正该差异涉及的局部逻辑；不得整文件回退 10-05 之后的安全修复。
- 若原始 T265 四元数相对独立真值在静止后缓慢漂移，先排除 USB 丢帧/时间映射、镜头纹理与光照、支架移动和启动会话不一致。能改善物理条件的先在相同代码下复测；仍存在系统性漂移时，提出有可靠外部航向约束的定位融合方案，并用同输入离线验证。**不得**直接冻结停车后 yaw、加入固定 ±3° 补偿、调大 SLAM 创新门限或在行驶中停下来等 T265 收敛；这些做法会隐藏真实转动或破坏连续任务。
- 若误差仅发生在融合层，检查 `map_T_t265_odom` 和锚点偏航新息的时序与迁移；若仅与动作控制时序相关，才重新审视停止判据/控制器。每种修复均需保持传感器真实失效时停车，不修改 C10B 协议和现有限速。

开发路径为 PC 局部代码改动 → 纯逻辑测试及旧日志回放 → 提交推送 GitHub → 板端只读核查干净且可快进 → `git pull --ff-only` → 先静态与无电机预检，再由现场批准一条一条动作。不要让实验性的旧阶段 4 脏工作树在板端直接覆盖当前代码。

### 6.3 修复后验收矩阵

| 项 | 样本与要记录的结果 | 合格判定 |
| --- | --- | --- |
| 静置 T265/SLAM | 新会话 ≥30 秒 ×3；真值、原始/适配/融合 yaw、confidence、锚点、扫描/TF 速率 | 无无解释的角度漂移/丢帧；静止预检能稳定获得已接受锚点 |
| 手动 ±90° | 每方向 ≥3，停稳后 ≥3 秒 | T265 相对外部真值的偏差与停后漂移在事先测得的不确定度内；结果逐条列出，不只报均值 |
| 自动 ±90° | 每方向至少 3 条**有效**样本，命令与物理停止分别标时 | 外部真值的最终角度逐条与目标相比；以原有 ≤0.5° 水平作为恢复目标，测量不确定度必须足以区分 0.5°；同时报告 T265/融合误差，任何一条超限不写“三次全通过” |
| 直行与健康锚点 | 前进 +50 cm、后退 −50 cm 各 ≥3；自然离群另作事件样本 | 不低于历史前进/后退有效样本的可比表现；共识期间连续，孤立离群不跳变，真失效保护不退化 |
| 任务入口抽样 | 先 `drive_distance`，再选择实际任务使用的 `drive_to`、`follow_segment` 等入口，每项至少 1 条、再按异常补样 | 无因偏航修复引入的终点自转、持续追打或假 SLAM 停车；配置与单动作工具一致 |

对 0.5° 目标，若外部设备不具备足够分辨率，结论必须写“本轮无法判定”，不能用 T265 自身读数冒充真值。任何失效/碰撞/场地空间不足/人员遮挡样本都保留原始文件和原因，但不计入有效重复次数。逐条提供起止角、停止时角、停后 0.2/0.5/1/2/3 秒角、真实与 T265/融合的偏差、最大锚点新息、状态序列、指令积分和事件丢失数。
